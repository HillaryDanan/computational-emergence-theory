**Thank you for your interest in contributing!** 🎉

This is **active research** on multi-scale emergence from individual agents to collective intelligence. We welcome contributions from:
- Researchers testing predictions across organizational scales
- AI practitioners building hybrid human-AI systems
- Social scientists studying collective intelligence

- Engineers implementing emergence-aware architectures

## 🌟 Ways to Contribute

### 1. Test Predictions (Highest Priority!)

We have **predictions spanning four organizational levels** (agents, dyads, groups, populations) waiting for empirical validation.

**How to contribute:**
1. Pick a prediction from [`predictions/`](predictions/)
2. Read the `protocol.md` (detailed experimental design)
3. Identify required level(s): Level 3 (agents), 4 (dyads), 5 (groups), or 6 (populations)
4. Run the experiment following the protocol
5. Document your findings (confirming OR disconfirming!)
6. Submit via Pull Request or Discussion

**Priority predictions:**
- **P4:** Collective intelligence composition (Level 5) - Most immediately testable
- **P5:** Phase transition thresholds (Level 6) - High practical impact
- **P1:** Substrate-agency relationships (Level 3) - Foundational validation
- **P7:** Consciousness-architecture correlations (cross-level) - Theoretical importance

**We value negative results equally!** If a prediction fails, that's crucial scientific information.

**Get credit:** Contributors who test predictions will be acknowledged in:
- The repository (contributors.md)
- Any publications arising from this work
- Co-authorship if contribution is substantial

## 📋 Contribution Process

### Small Changes (typos, clarifications, small additions)

**Direct Pull Request:**
1. Fork the repository
2. Create a branch: `git checkout -b fix-paper2-typo`
3. Make your changes
4. Commit with clear message: `Fix typo in Paper 2 Section 4.3`
5. Push and create Pull Request
6. Wait for review (usually within a week)

### Large Changes (new implementations, major content)

**Start with Discussion:**
1. Open an [Issue](../../issues) or [Discussion](../../discussions) first
2. Describe what you want to add/change and why
3. Specify which level(s) it addresses
4. Get feedback before investing significant time
5. Then follow PR process above

**Why?** Prevents wasted effort if the change doesn't align with project goals.

## ✅ Standards & Guidelines

### Scientific Rigor

**Required for all contributions:**

1. **Cite sources** for factual claims
   - Prefer peer-reviewed publications
   - Mark non-peer-reviewed sources as such
   - Link to papers when possible
   - **For consciousness claims:** Cite established neuroscience, acknowledge uncertainty

2. **Mark confidence levels**
   - High confidence: Direct measurements, replicated findings (most substrate facts, collective intelligence data)
   - Medium confidence: Indirect evidence, theoretical extrapolations (some consciousness correlates, emergence operators)
   - Low confidence: Speculation requiring validation (phenomenal experience, collective consciousness)

3. **Distinguish fact from hypothesis**
   - "Studies show X [citation]" ← fact
   - "We hypothesize Y" ← hypothesis
   - "Z is possible but unproven" ← speculation
   - **Especially important for Paper 3 (consciousness)**

4. **Be honest about limitations**
   - What data is missing?
   - What assumptions are we making?
   - What alternative explanations exist?
   - What can't we currently measure? (e.g., phenomenal experience)

5. **Reproducibility**
   - Provide enough detail that others can replicate
   - Share data, code, and protocols
   - Document software versions, parameters, methods
   - Pre-register experiments when possible

### Multi-Scale Thinking

**For contributions spanning levels:**
- Clearly specify which level(s) you're addressing
- Define emergence operators connecting levels
- Validate that macro-variables have predictive power
- Don't claim emergence without demonstrating information compression + causal autonomy

**Example:**
- "This group-level property emerges from individual interactions" ← vague
- "We define coarse-graining function Φ mapping individual states to group state, showing I(macro; future) ≈ I(micro; future) with 90% compression" ← good

### Writing Style

**Balance accessibility with precision:**
- Define technical terms on first use
- Use concrete examples (real agents, real groups)
- Include plain language summaries for technical sections
- Maintain scientific accuracy—don't oversimplify
- Use level-specific language appropriately (agent vs collective vs population)

**Avoid:**
- Unsupported claims (especially about consciousness)
- Exaggerated language ("proves", "definitively shows")
- Jargon without explanation
- Anthropomorphizing collective systems inappropriately
- Claiming to solve the hard problem of consciousness

**Good examples:**
- "Evidence suggests collective intelligence factor c correlates with turn-taking equality (Woolley et al., 2010)"
- "We predict substrate properties constrain agent capabilities; this is testable via Prediction 1"
- "Functional correlates of consciousness include φ and temporal binding; phenomenal experience remains unmeasured"

### Code Quality

**For implementations:**
- **Documented:** README + docstrings + inline comments
- **Modular:** Separate concerns by level (agent vs group vs population)
- **Tested:** Include tests or example usage
- **Readable:** Follow PEP 8 (Python) or language conventions
- **Dependencies:** List all requirements with versions
- **Level-appropriate:** Agent code in `implementations/agent_modeling/`, etc.

## 🔬 Experimental Contributions

### Pre-Registration (Recommended)

**For testing predictions:**

1. Before running experiments, create an [Issue](../../issues) describing:
   - Which prediction you're testing
   - Which level(s) it addresses
   - Your methodology
   - Expected timeline
   - How you'll analyze results

2. This creates a public record (pre-registration)
3. Prevents "p-hacking" or selective reporting
4. Increases credibility of findings

**Not required, but strongly encouraged for scientific integrity.**

### Multi-Level Studies

**If your experiment spans multiple levels:**
- Clearly define measurements at each level
- Specify emergence operators connecting levels
- Validate that coarse-graining preserves information
- Test predictions at each level independently

**Example:** Testing group collective intelligence (Level 5)
- Measure: Individual abilities (Level 3), dyad interactions (Level 4), group performance (Level 5)
- Validate: Group performance not reducible to sum of individual abilities
- Demonstrate: Emergent group-level properties with causal power

### Reporting Results

**Include:**
- Detailed methodology (enough for replication)
- Clear specification of level(s) studied
- Raw data (when shareable)
- Statistical analysis with confidence intervals
- Limitations and potential confounds
- Discussion of how findings relate to framework predictions

**Report EVERYTHING:**
- Confirming results ✓
- Disconfirming results ✓
- Null results ✓
- Unexpected findings ✓
- Mixed results (some levels confirm, others don't) ✓

**All outcomes are valuable!** Don't suppress disconfirming evidence.

## 📝 File Organization

### Adding New Content by Level

**Follow the [structure guidelines](STRUCTURE.md):**

**Agent-level (Level 3) implementation?**
→ `implementations/agent_modeling/your_module.py`

**Group-level (Level 5) analysis?**
→ `implementations/collective_intelligence/your_module.py`

**Population-level (Level 6) simulation?**
→ `implementations/population_dynamics/your_module.py`

**Cross-level emergence operator?**
→ `theory/emergence_operators.py`

**New prediction?**
→ `predictions/08_new_prediction/protocol.md` (specify level(s))

**See [STRUCTURE.md](STRUCTURE.md) for detailed guidelines.**

### File Naming

- Use `snake_case`: `group_dynamics_model.py`
- Be descriptive: `phase_transition_detector.py` not `analysis.py`
- Indicate level if appropriate: `level5_collective_intelligence.py`
- Date experimental data: `results_2025_11_16.csv`

## 🎯 Review Process

### What Reviewers Check

**Scientific Content:**
- Are claims supported by evidence?
- Are citations appropriate?
- Are limitations acknowledged (especially for consciousness)?
- Is reasoning sound?
- Are level boundaries clearly defined?
- Do emergence operators make mathematical sense?

**Multi-Scale Consistency:**
- Are levels clearly specified?
- Are emergence operators well-defined?
- Is macro-level genuinely emergent (not just aggregated)?
- Are cross-level connections validated?

**Clarity:**
- Is writing clear?
- Are explanations accessible?
- Are figures/code documented?
- Is level-specific terminology used appropriately?

**Structure:**
- Does it fit repository organization by level?
- Are files named appropriately?
- Is documentation complete?

### Response Time

- **Simple fixes:** Usually within 3-5 days
- **Major contributions:** May take 1-2 weeks for thorough review
- **Complex multi-level experiments:** May require multiple rounds of discussion

**Be patient!** We're committed to thoughtful review over speed.
